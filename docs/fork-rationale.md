# What upstream needs before SeerrNG can disappear

**Last updated: November 1, 2026.**

SeerrNG is maintained as a separate fork so it can add cross-media workflows
and adapt selected Seerr changes for its users. This matrix records what a
supported replacement would need to preserve before SeerrNG users could move
off the core fork. SeerrNG is a fork of Seerr maintained by snapetech; linked
Seerr issues and pull requests identify compatibility context and do not imply
that the referenced work has shipped. Upstream does not need to accept the same
patches: a maintained extension, adapter, or compatible service can satisfy a
gate if it provides the behavior users rely on.

**First-admin media-server provisioning.** A replacement must create the first
administrator without overwriting a preconfigured Jellyfin or Emby connection
or API key. It may create a provider-side key when none exists and should use
setup values for the endpoint only when no endpoint is already configured.
Source context includes Seerr [issue #3618](https://github.com/seerr-team/seerr/issues/3618),
which upstream closed as not planned after classifying the request as new setup
behavior. Close this gate after a first-admin sign-in against a preconfigured
server preserves its endpoint and key without creating a duplicate, while an
unset key is created and an unset endpoint uses validated setup values.

The rows describe retirement requirements, not current upstream coverage.
Source links provide public context only; they do not mean upstream has shipped
the behavior. Work that has not shipped in a supported SeerrNG release is not
a user-facing retirement blocker unless it is adopted before the move. Close a
gate only after its replacement is available in a supported release and the
required migration and operator path have been checked.

**Status API and version checks.** A replacement should cache successful GitHub
release and commit lookups for six hours and hold failed lookups for five
minutes, so repeated `/api/v1/status` polling does not retry an unavailable or
rate-limited GitHub request on every poll. Source context includes Seerr
[issue #3665](https://github.com/seerr-team/seerr/issues/3665). Close this gate
after repeated status polls under successful, rate-limited, and timed-out GitHub
responses remain truthful about update-check success, bound external requests,
and retry only after the relevant cache interval.

| Media scope | The categories SeerrNG users still rely on: movies, series, music, ebooks and audiobooks, comics, magazines, emulation ROMs, and PC games. Source context includes Seerr [issue #3394](https://github.com/seerr-team/seerr/issues/3394) and the related [PR #2039](https://github.com/seerr-team/seerr/pull/2039). | Checks cover legacy placeholders, chained allowlisted filters, Unicode text, unknown and malformed filters, nested JSON values, and payload size/depth limits. |
| Data and API transition | A supported path preserves or intentionally transforms requests, user preferences, permissions, provider links, API clients, and other state operators need. | A representative SeerrNG backup upgrades to the supported replacement in a disposable environment. Data integrity, client compatibility, rollback, and recovery are documented and verified. |
| Container distribution and identity | Production images omit build-only payloads that are not required at runtime; Docker examples drop all Linux capabilities, prevent privilege escalation, and describe the container's UID/GID behavior and rootless Podman mapping. Source context includes Seerr [PR #3472](https://github.com/seerr-team/seerr/pull/3472), [issue #3598](https://github.com/seerr-team/seerr/issues/3598), and [issue #3602](https://github.com/seerr-team/seerr/issues/3602). | Compare current compressed and unpacked image sizes; verify startup and config-volume writes with the dropped capabilities, documented container identity, and rootless Podman mapping. |
| Release and operator support | Installation, configuration, backup, upgrade, rollback, troubleshooting, and support guidance cover the deployment channels SeerrNG users rely on. Notification setup documentation explains provider-specific options for posters, priorities, sounds, public logos, webhook variables, and SMTP certificate verification. Source context includes Seerr [PR #3586](https://github.com/seerr-team/seerr/pull/3586); SeerrNG maintains corresponding [notification guides](./using-seerr/notifications/index.mdx). | Operators can move from a supported SeerrNG release to a supported replacement using documented steps and a tested recovery path. Notification documentation must match the shipped settings and explain security-sensitive transport options. |
| Helm release resources | The Kubernetes chart can render administrator-supplied resource objects under the same release lifecycle. Entries are schema-checked, can use chart values and named templates, and default to no extra resources. Source context includes Seerr [PR #3388](https://github.com/seerr-team/seerr/pull/3388). | Helm validation confirms empty defaults and representative configured resources render correctly; release upgrades and uninstall own the extra objects; chart and operator documentation match the accepted value schema. |
| Helm maintenance scaling | Kubernetes packaging can stop the single SeerrNG application instance during storage maintenance or backups and resume it afterward without deleting the configuration claim. Source context includes Seerr [PR #3629](https://github.com/seerr-team/seerr/pull/3629). | Chart rendering accepts 0 or 1 replica, rejects negative or multiple replicas, and preserves the configuration claim through scale-down and recovery. |
| Companion services | BookshelfNG, ChaptarrNG, QuestarrNG, and ROMarrNG remain usable through supported APIs, adapters, or extensions. Retiring SeerrNG does not itself retire a companion project. | Each companion integration needed by users has a maintained compatibility path; companion-fork retirement stays a separate decision with its own criteria. |
| Provider removal and request history | Removing a copy from its selected acquisition service updates the matching service and availability state while preserving the SeerrNG media record, requests, and status history. Clear Data remains the separate explicit action for removing that record and its requests. Source context includes Seerr [PR #3288](https://github.com/seerr-team/seerr/pull/3288). | Checks cover removal from one quality, format, or destination without losing request history, with the distinct Clear Data confirmation and effect. Other service links and availability remain intact. |

The matrix is a retirement checklist, not a claim that a particular upstream
release already satisfies it. A fork, extension, adapter, or compatible
service can replace a gate once the behavior is supported and the evidence is
available. The [documentation index](./README.md) links to current operator
guides; [NOTICE.md](https://github.com/snapetech-org/seerrng/blob/main/NOTICE.md)
records project attribution.
