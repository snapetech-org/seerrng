# API and notification localization audit

The API-message inventory records app-authored fixed wording and opaque captured values separately. `bin/update-api-message-catalog.mjs` scans authored response fields, HTTP errors, persisted status fields, helper returns, and error candidates; it generates stable source-hash message IDs and literal/template matchers. Its 2,501 entries are candidates for display, including internal errors that may never be exposed. The inventory does not claim that internal logging is translated. Empty values, dynamic data, short data assembly, protocol/control-flow codes, and HTML response documents are recorded separately (1,566 records).

Only explicit display boundaries use these messages. `ApiMessageText` reads the current UI locale at render, isolates captured values, and leaves unknown strings and React content intact. The string helper handles accessibility text and translated template parameters without changing the original API object or control-flow value. Toasts, direct response errors/notices, persisted request/software/download status, and remaining reason/diagnostic displays use these boundaries. Matching uses literal fragments and bounded input rather than backtracking regular expressions.

`bin/check-api-message-surfaces.cjs` inventories 125 JSX message/error/status surfaces. Its manual classifications identify localized state and validation, rich-text callback arguments, translated child boundaries, user-authored issue comments, dynamic provider recommendations and service/media data, and operational log records. A new or changed unclassified surface fails the check. The separate raw JSX screen found 31 proper-name, URL, code, entity, and unit candidates; direct app-authored accessibility templates discovered by the audit now have message IDs.

Notification content is resolved for each recipient at delivery time. Optional finite descriptors cover media events, issue/comment headings, fallback bodies/subjects, and fixed extra labels. They survive bounded outbox serialization and validation; unknown descriptor values are rejected. Original user comments, provider descriptions, media titles, requester values, service names, identifiers, and custom JSON/protocol data remain data. Legacy/custom payloads without descriptors remain compatible. Email, push, chat, and webhook content builders use the recipient/configured locale; custom webhook keys, template text, and protocol fields remain unchanged.
